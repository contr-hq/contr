The first preview of the Contr core: the `contrd` daemon, the `contr` command line and the engine they run. It is an
early build for trying Contr out and for building the desktop apps against; expect rough edges.

## What's in this release

**Windows (WSL 2)**

- Runs Moby 29.9.1 in two Contr-owned WSL 2 distributions: one for the engine, one for its data, so updating the
  engine keeps your images, containers and volumes.
- Serves the engine on a per-user named pipe and on `\\.\pipe\docker_engine` when no other program uses it, and keeps
  a `contr` Docker CLI context pointed at it.
- Windows paths work in bind mounts (`-v C:\src:/src`), and `host.docker.internal` reaches services on Windows,
  including those listening only on `localhost`.
- `contr cli install` installs Docker CLI 29.9.1, Compose 5.6.0, Buildx 0.38.0 and the Windows credential helper for
  your user and adds them to your PATH.
- `contr wsl enable <distribution>` gives your own WSL 2 distributions `docker`, Compose and Buildx on the same
  engine, including bind mounts of their own paths.
- The engine restarts by itself when WSL shuts down underneath it.

**Linux**

- Manages the Docker Engine or Podman already installed on the host: rootless Docker, then rootful Docker, then
  Podman.

**Everywhere**

- `contr start`, `stop`, `status`, `ps`, `exec`, and `contr reset` (add `--factory` to delete all engine data).
- `contr doctor` checks what keeps the engine or its features from working, and `contr fix <action>` runs the fixes
  it offers, such as installing WSL.
- `contr settings` shows and changes settings; administrators can fix settings for every user (see the README).
- A gRPC API with Rust and C# SDKs covering containers (create, run, logs, stats, exec, pause, kill, rename,
  prune), images (pull, inspect, remove, prune), volumes, networks, engine usage, diagnostics, settings and
  integrations.

The Windows executables need no Visual C++ Redistributable or other runtime.

## Try it

**Windows**: unzip the archive, then in a terminal in that folder:

```powershell
.\contr.exe start
.\contr.exe cli install
```

Then open a new terminal, which finds the installed `docker`, and run:

```powershell
docker run --rm hello-world
```

If WSL is missing, `contr start` says so; `.\contr.exe fix install-wsl` installs it after one administrator prompt,
and Windows may ask you to restart.

**Linux**: with Docker Engine or Podman installed, unpack the archive and run:

```sh
./contr start
docker --context contr run --rm hello-world
```

## Known limitations

- The executables are not code-signed yet, so Windows SmartScreen may warn before they run.
- Compose project actions and Kubernetes are not available yet.
- There are no deb or rpm packages yet, and on Linux Contr cannot yet install an engine or set up rootless Docker for
  you.
- Installing WSL downloads it from Microsoft.
