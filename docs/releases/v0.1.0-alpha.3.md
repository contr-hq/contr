The third preview of the Contr core: the `contrd` daemon, the `contr` command line and the engine they run. The
desktop apps for Windows and Linux are released from their own repositories, built on this core. It is still an early
build; expect rough edges.

## What's new

**Work that keeps going**

- Pulls, pushes, Compose actions, Kubernetes image imports, diagnostics bundles, fixes, and engine start, stop,
  restart and reset now run in the daemon. They go on when the app that started them leaves the page, closes its
  window or quits. Every app sees them, follows their progress and can cancel them; engine operations and fixes run
  to the end once started.
- Starting work that is already running joins it, so the same pull or bundle never runs twice. A second Compose
  action on the same project is refused until the first one ends.
- The command line still cancels its own pull, push or Compose action on Ctrl+C.
- The API grows to revision 22 with the operations service. The Rust and C# SDKs cover it.

**Published ports on Windows**

- A port a container publishes listens on Windows at the address Docker reports, without relying on WSL's localhost
  forwarding. `-p 8080:80` listens on every interface, and `-p 127.0.0.1:8080:80` on loopback only.
- Other computers reach a published port once an administrator allows Contr daemon in Windows Firewall; the
  [README](https://github.com/contr-hq/contr#published-ports-and-windows-firewall) has the steps. On the computer
  itself it works without that.

**Security**

These fixes follow the [security review](https://github.com/contr-hq/contr/blob/main/docs/security-review.md) of
0.1.0-alpha.2:

- Apps and the command line connect only to a daemon pipe that belongs to the signed-in user, so another user of the
  same Windows computer cannot stand in for the daemon.
- The pipe `docker` uses for the engine gets a new random name each time the daemon starts.
- `wsl.exe` always runs from System32, including when installing WSL needs an administrator.
- The settings file and the kubeconfig's staging copy are readable by their owner only.
- The Kubernetes server runs only k3s images pinned by digest.
- Tokio is updated to 1.54.1 for RUSTSEC-2026-0384.

## Verifying downloads

Every file carries a GitHub build attestation (`gh attestation verify <file> --repo contr-hq/contr`), and
`SHA256SUMS` is signed with the project's key at
<https://contr-hq.github.io/contr-packages/checksums/contr/v0.1.0-alpha.3/>. See
[Verifying downloads](https://github.com/contr-hq/contr/blob/main/docs/verifying.md) and the
[Code signing policy](https://github.com/contr-hq/contr/blob/main/docs/code-signing-policy.md).

## Known limitations

- The Windows executables are not code-signed yet, so Windows SmartScreen warns before they run, and Smart App
  Control may block them. Verify them as above.
- Published UDP ports on Windows still depend on WSL's localhost forwarding.
- Operations exist only while the daemon runs; stopping the daemon cancels the ones that can be cancelled.
- Builds are for x64 only.
- Installing WSL downloads it from Microsoft, and `contr fix install-engine` downloads from your distribution's
  mirrors.
